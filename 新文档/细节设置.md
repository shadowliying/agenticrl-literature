# **奖励**

**两段式奖励总览**  
目标：前段强化“过程正确”（检索质量/验证充分），后段逐步提高“最终答案质量”的权重，但不让终局奖励压过过程反馈。  
前提：只在 `ANSWER` 动作触发时计算 `R_quality`，其它动作该项为 0。

---

**阶段一：过程强化段（更强调中间反馈）**  
适用：训练不稳定、检索噪声多、经常绕圈或过度搜索的情况。  
权重建议（总和=1）：

- `R_quality = 0.25`
- `R_sufficiency = 0.35`
- `R_info_gain = 0.25`
- `R_efficiency = 0.15`

**解释**  
- `R_sufficiency`（验证充分度）最高，鼓励“证据足够再回答”。  
- `R_info_gain`（信息增量）和 `R_efficiency`（效率）压住“无效检索/重复检索”。  
- `R_quality` 仅在 `ANSWER` 时生效，占比更低，避免长链路奖励太远。

**阶段一的计算细节（完整定义建议）**  
1. `R_sufficiency`  
   - 由 Validate 返回：`sufficiency_score` ∈ [0,1]  
   - 建议构成：  
     - 覆盖率：必须槽位/关键信息点覆盖数 ÷ 总槽位数  
     - 一致性：证据间冲突惩罚  
   - 公式例子：  
     - `sufficiency_score = clip(coverage - 0.5*conflict, 0, 1)`  
2. `R_info_gain`  
   - 衡量新检索结果的**新信息比例**  
   - 公式例子：  
     - `info_gain = new_facts / (new_facts + repeated_facts + 1e-6)`  
   - 或：`1 - Jaccard(new_snippets, previous_snippets)`  
3. `R_efficiency`  
   - 对动作成本惩罚（越多步骤越惩罚）  
   - 公式例子：  
     - `efficiency = exp(-step_count / k)`  
     - 或 `1 - min(step_count / max_steps, 1)`  
4. `R_quality`  
   - 只在 `ANSWER` 动作时计算，其他动作=0  
   - 指标可由 LLM 或规则打分（结构、引用、事实一致性等）  

---

**阶段二：质量平衡段（逐步提高终局质量）**  
适用：策略趋于稳定，检索不再反复、验证足够时。  
权重建议（总和=1）：

- `R_quality = 0.40`
- `R_sufficiency = 0.25`
- `R_info_gain = 0.20`
- `R_efficiency = 0.15`

**解释**  
- 在仍保持过程反馈的情况下，开始强调最终答案质量。  
- 仍保留 `R_sufficiency` 与 `R_info_gain` 以防“凭空回答”。

---

**两段切换规则（只用两段，不再细分）**  
选择一个即可，推荐第 1 个，简单可解释：

1. **固定步数切换（推荐）**  
   - 前 `N` 个训练步骤用阶段一  
   - 后续全部用阶段二  
   - 例如：`N = 60%` 总训练步数  
2. **稳定性切换（更精准）**  
   - 当最近 `K` 个 batch 内：  
     - `sufficiency` 均值 ≥ 0.75  
     - `info_gain` 均值 ≥ 0.5  
     - 且方差下降（稳定）  
   - 触发从阶段一切到阶段二  
   - 这是“质量已稳定、再强调终局”的逻辑

---

**关键细节（你担心的“奖励过远”问题）**  
- **答案奖励只在 ANSWER 时给**，否则=0。  
- **过程奖励每步都有**，避免“奖励路径过远”。  
- `R_sufficiency` 是系统里最强的过程信号，可直接来自 Validator。  
- 惩罚项存在且明确，比如：  
  - 重复搜索惩罚  
  - 空检索/无文档惩罚  
  - `ANSWER` 在 `sufficiency < 0.6` 时惩罚  

---

**最终统一公式（两段都用同一公式，只换权重）**  
```
R_total = w_quality * R_quality
        + w_sufficiency * R_sufficiency
        + w_info_gain * R_info_gain
        + w_efficiency * R_efficiency
        - w_penalty * R_penalty
```

`R_penalty` 例子：  
- 重复检索：+0.2  
- 连续空检索：+0.3  
- 低 sufficiency 强行回答：+0.5  


# **validate**

下面给你一个**可直接落地**的 Validate 评分框架：它回答两个问题：  
1) 证据是否“足够充分”可以回答；  
2) 证据是否“可信且一致”。

我分成**评分维度 + 硬性门槛 + 综合判定**三部分，保证你面试时能讲清楚逻辑链。

---

**一、Validate 的评分维度（打分项）**  
建议每次检索后都给分，用于过程奖励与是否继续检索。

1. **覆盖度（Coverage / Sufficiency Core）**  
   - 判断问题的关键槽位是否被证据覆盖  
   - 槽位例子：主体实体、时间范围、地点、数量、限制条件、对比对象等  
   - 评分方式：  
     - `coverage = 已覆盖槽位数 / 总槽位数`  

2. **相关性（Relevance）**  
   - 证据是否直接回答当前子问题，而不是泛泛相关  
   - 可用轻量检索打分 + LLM 判别  
   - 评分方式：0~1  
   - 如果大部分文档只“弱相关”，即使 coverage 高也要扣分

3. **支持强度（Support Strength）**  
   - 证据是否清晰、可引用、非模糊  
   - 例如“明确数字/定义/原文”优于“泛描述”  
   - 评分方式：0~1

4. **一致性（Consistency）**  
   - 多文档之间是否互相矛盾  
   - 有冲突就扣分  
   - 评分方式：  
     - `consistency = 1 - conflict_ratio`  

5. **冗余与新信息比例（Info Gain）**  
   - 新检索是否带来新信息，而非重复  
   - 重复越多，说明继续检索收益越低  
   - 评分方式：0~1

6. **来源可信度（Source Quality）**  
   - 权威来源 > 论坛/博客  
   - 可按白名单或域名规则打分  
   - 评分方式：0~1

7. **时效性（Freshness）**  
   - 与问题时间要求匹配  
   - 例如“2024 年后”问题，旧文档扣分  
   - 评分方式：0~1  

---

**二、硬性门槛（必须满足，否则直接判不足）**  
这些是“阻断条件”，即使综合得分高也不能放行：

1. **关键槽位缺失**  
   - 主体实体、时间范围、核心指标没有证据  
2. **证据冲突严重**  
   - conflict_ratio 超过阈值（如 >0.4）  
3. **高风险问题缺乏权威来源**  
   - 医疗/法律/金融类必须来源可信  
4. **需要多源交叉但只有单一来源**  
   - 比如争议性事实  

---

**三、综合评分公式（输出 sufficiency_score）**  
建议使用加权评分，面试里这样讲很清楚：

```
sufficiency_score =
  0.35 * coverage
+ 0.20 * relevance
+ 0.15 * support_strength
+ 0.10 * consistency
+ 0.10 * source_quality
+ 0.05 * freshness
+ 0.05 * info_gain
```

然后结合硬性门槛：

- 如果触发门槛 → `sufficiency = false`  
- 否则：  
  - `sufficiency_score >= 0.75` → 足够  
  - `0.60 ~ 0.75` → 边缘（可少量补检索）  
  - `< 0.60` → 不足，继续检索  

---

**四、最终 Validate 的结构化输出（建议）**  
让 Validate 返回结构化 JSON，更可控：

```json
{
  "sufficiency": false,
  "sufficiency_score": 0.62,
  "coverage": 0.5,
  "missing_slots": ["时间范围", "统计口径"],
  "conflicts": ["来源A与来源B结论不一致"],
  "suggested_action": "search_more",
  "next_query_hint": ["补充时间范围", "找官方统计口径"]
}
```

---

**五、如何解释给面试官**  
一句话总结：  
Validate 不是简单打分，它是“结构化需求覆盖 + 证据可信一致性”的双重判断。即便最终答案质量高，若证据覆盖不足，也不给放行。这让奖励从“终点”移到“过程”。
