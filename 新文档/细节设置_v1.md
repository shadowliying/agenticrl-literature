# 细节设置（v1）

本文件用于统一 v1 系统的“验证 + 奖励 + 结构化执行”细节。

---

## 1. Validate 结构化评分

**评分维度**（0~1）：
- coverage（覆盖度）
- relevance（相关性）
- support_strength（支持强度）
- consistency（一致性）
- info_gain（信息增益）
- source_quality（来源质量）
- freshness（时效性）

**综合评分公式**
```
sufficiency_score =
  0.35 * coverage
+ 0.20 * relevance
+ 0.15 * support_strength
+ 0.10 * consistency
+ 0.10 * source_quality
+ 0.05 * freshness
+ 0.05 * info_gain
```

**硬性门槛**（触发则直接不足）
- 关键槽位缺失
- 冲突比例 > 0.4
- 高风险问题但来源质量 < 0.4
- 时间敏感问题但时效性 < 0.4

**输出字段（JSON）**
```
{
  "sufficiency": true/false,
  "sufficiency_score": 0.0-1.0,
  "missing_slots": [],
  "conflicts": [],
  "suggested_action": "search_more | replan | synthesize"
}
```

---

## 2. 两段式奖励（SFT → GRPO）

**阶段一（过程强化）**
- R_quality = 0.25
- R_sufficiency = 0.35
- R_info_gain = 0.25
- R_efficiency = 0.15

**阶段二（质量平衡）**
- R_quality = 0.40
- R_sufficiency = 0.25
- R_info_gain = 0.20
- R_efficiency = 0.15

**切换规则**
- 训练进度 ≥ 60% 自动切换
- 或 sufficiency 与 info_gain 稳定后切换

---

## 3. 执行流程（Plan + StateMachine）

流程示意：
`PLAN → MEMORY(Recall) → RETRIEVE → VALIDATE → (REPLAN | SYNTHESIS) → ANSWER → MEMORY(Write)`

---

## 4. SFT 对齐重点

SFT 阶段重点约束：
- 输出格式严格 JSON
- 结构化 Plan 输出正确字段
- Validate 输出字段与类型正确
- 禁止输出额外解释
