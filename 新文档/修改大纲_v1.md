# 修改大纲（基于现有文档与当前代码现状）

> 目标：在你原本的“普通 agent 项目”基础上，完成 **结构化计划 + 状态机执行 + GRPO 过程强化** 的升级，同时 **精简 agent 数量**，强化 Validate 过程判断与奖励信号，使整条链路更可解释、可训练、可面试表达。

---

## 修改总览（先锁范围）

**要改**
- 把字符串流程替换为结构化 Plan 与状态机执行。  
- 精简 Agent 角色，合并职责，降低链路冗余。  
- Validate 改为结构化评分与硬性门槛。  
- GRPO 只作用在 Orchestrator 的策略层，采用两段式奖励。  

**要增加**
- PlanSchema、StateMachine、ReplanTrigger。  
- Evidence 映射与检索去重。  
- 结构化轨迹日志（state/action/reward/evidence/validate）。  
- Memory Layer（短期/长期记忆）与 Memory Recall/Write 步骤。  

**要合并或下线**
- Reorchestrator 并入 Orchestrator。  
- Optimizer/Search/Selector 合并为 RetrievalAgent。  
- Code/Assistant 合并为 SynthesisAgent。  

---

## 1. 总体架构调整（从“字符串流程”到“结构化计划+状态机”）

**要改**
- 把当前 `search_process` 字符串流程改成结构化 Plan JSON。  
- 用状态机驱动执行，避免依赖字符串解析。  
- 将重规划逻辑并入 Orchestrator 决策层。  

**要增加**
- PlanSchema（建议 JSON 或 dataclass）。  
- StateMachine（状态转移表）。  
- ReplanTrigger 规则（低覆盖、冲突过高、重复检索）。  

---

## 2. Agent 层精简与职责重构（保持描述完整，但角色更少）

**现状**
- Orchestrator / Optimizer / Search / Selector / Validator / Reorchestrator / Code / Assistant

**修改目标**
- 精简为 4 个核心 Agent。  

**要改**
- Orchestrator：输出结构化 Plan，负责动作选择与重规划，是 GRPO 训练对象。  
- RetrievalAgent：合并 Optimizer+Search+Selector，负责查询生成、检索、去重、轻量排序、摘要。  
- ValidatorAgent：结构化判定“是否充分”，输出分数与缺失信息。  
- SynthesisAgent：生成最终答案，必要时调用 Code 工具。  

**补充说明**
- Memory 不作为独立 Agent，而是能力层（Memory Layer）。  
- 在流程中以 Memory Recall / Memory Write 形式嵌入。  

---

## 2.1 Memory 设计（模块而非 Agent）

**定位**  
- Memory 是能力模块，不参与策略决策，只负责“存/取/检索”。  

**建议形态**  
- 短期记忆：当前任务上下文（对话历史、已检索证据）。  
- 长期记忆：跨会话知识（用户偏好、历史结论、稳定事实）。  

**接入点**  
- PLAN 之后：Memory Recall（补充背景与约束）。  
- ANSWER 之后：Memory Write（写入摘要与结论）。  

**要增加**
- Orchestrator 内引入策略输出接口，支持 RL/GRPO。  
- RetrievalAgent 支持 query 改写、多查询融合、轻量 rerank。  

---

## 3. Validate 模块重写（从“简单判断”到“可解释评分体系”）

**要改**
- Validate 不再只返回布尔，而是输出结构化评分。  
- 判定逻辑从“是否有内容”改为“覆盖关键槽位 + 一致性 + 可信度”。  

**要增加**
- 评分维度：coverage / relevance / support_strength / consistency / info_gain / source_quality / freshness。  
- 硬性门槛：关键槽位缺失、证据冲突严重、可信度不足。  
- 输出字段：sufficiency_score、missing_slots、conflicts、suggested_action。  

---

## 4. GRPO 集成（只做两段式，不再三段）

**要改**
- GRPO 只作用在 Orchestrator 的动作策略层。  
- 奖励从“终局质量为主”改为“过程奖励为主 + 终局保留”。  
- 训练顺序调整为 **先 SFT（LoRA）再 GRPO（LoRA）**，提升稳定性与格式对齐。  

**要增加**
- SFT 数据与格式约束（指令遵循、Plan/Validate 结构化输出）。  
- 两段式权重：  
  阶段一（过程强化）：R_quality 0.25 / R_sufficiency 0.35 / R_info_gain 0.25 / R_efficiency 0.15。  
  阶段二（质量平衡）：R_quality 0.40 / R_sufficiency 0.25 / R_info_gain 0.20 / R_efficiency 0.15。  
- 切换规则：训练步数比例切换，或 sufficiency + info_gain 稳定后切换。  

---

## 5. 检索与证据流重构（提升“检索质量反馈”权重）

**要改**
- Search 结果不直接进入答案，必须先经过 Validate。  
- 重排序时考虑“支持强度 + 来源可信度 + 新信息”。  

**要增加**
- 文档去重与证据片段抽取。  
- 证据映射结构（证据 → 覆盖槽位）。  

---

## 6. 回答与 Code 使用策略

**要改**
- 只有在“需要计算/表格/脚本”时才启用 Code。  
- 对于纯文本回答，直接用 SynthesisAgent 生成。  

**要增加**
- need_code 判断条件（统计计算、可视化、公式推导等）。  
- 代码输出与答案输出严格分离。  

---

## 7. 训练/评估日志与数据结构

**要改**

**要增加**
- 结构化轨迹记录（state/action/reward/evidence/validate）。  
- 训练数据缓存与回放。  
- 指标可视化：sufficiency 均值、info_gain 趋势、replan 次数。
