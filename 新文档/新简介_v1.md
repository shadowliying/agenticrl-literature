# 新系统简介（统一术语版本）

> 目标：把现有“普通 agent 项目”升级为 **结构化计划 + 状态机执行 + GRPO 过程强化** 的研究型问答系统，强调“过程可解释、检索可验证、奖励可追溯”，并精简 agent 数量。

---

## 1. 系统目标与原则

- 目标一：把“字符串流程”升级为结构化计划（Plan），避免逻辑靠文本解析。  
- 目标二：让执行由状态机驱动，支持可控的重规划与路径回退。  
- 目标三：用 GRPO 训练 Orchestrator 的策略，强化过程反馈而不是只看最终答案。  
- 目标四：把检索质量、证据充分性作为主反馈信号，避免“奖励路径过远”。  

---

## 2. 统一术语（面试口径可直接引用）

- **Plan（结构化计划）**：包含目标、子任务、输入输出、成功条件、依赖、回退条件的 JSON 或数据结构。  
- **StateMachine（状态机执行）**：基于状态转移表推进流程，避免依赖字符串解析。  
- **ReplanTrigger（重规划触发器）**：当证据不足、冲突严重、检索无增益时触发重规划。  
- **Evidence（证据片段）**：来自检索文档的可引用事实片段，用于覆盖关键槽位。  
- **ValidateScore（充分性评分）**：对证据的覆盖度、相关性、一致性、可信度等进行量化评分。  
- **Two‑Phase Reward（两段式奖励）**：阶段一强调过程反馈，阶段二提高终局质量权重。  
- **Policy Layer（策略层）**：Orchestrator 的动作选择逻辑，是 GRPO 的训练对象。  
- **Memory Layer（记忆层）**：作为能力模块，不是独立 Agent，负责记忆的存取。  
- **Memory Recall/Write**：在流程中回忆与写入的两个动作节点。  

---

## 3. 核心组件（精简后的 4 个 Agent）

- **Orchestrator**：生成 Plan，选择下一步动作，触发重规划，是 GRPO 训练主体。  
- **RetrievalAgent**：负责查询生成、检索、去重、轻量排序、摘要与证据抽取。  
- **ValidatorAgent**：对证据做结构化充分性评分，输出缺失点与下一步建议。  
- **SynthesisAgent**：在证据足够时生成最终答案，必要时调用 Code 工具。  
- **Memory Layer（能力模块）**：不作为 Agent，提供短期/长期记忆的读取与写入。  

---

## 4. 核心流程（结构化 + 状态机）

1. **PLAN**：Orchestrator 输出结构化 Plan。  
2. **MEMORY (Recall)**：从 Memory Layer 回忆背景、约束或历史结论。  
3. **RETRIEVE**：RetrievalAgent 执行检索与证据抽取。  
4. **VALIDATE**：ValidatorAgent 输出 sufficiency_score、缺失槽位与建议动作。  
5. **REPLAN 或 SYNTHESIS**：不足则重规划，足够则进入合成。  
6. **ANSWER**：SynthesisAgent 生成最终答案（必要时调用 Code）。  
7. **MEMORY (Write)**：将摘要与结论写入 Memory Layer。  

---

## 5. 两段式奖励（术语对齐）

- **阶段一：过程强化**  
  权重建议：`R_quality 0.25 / R_sufficiency 0.35 / R_info_gain 0.25 / R_efficiency 0.15`  
  目的：优先训练“检索质量与证据充分”，防止奖励路径过远。  

- **阶段二：质量平衡**  
  权重建议：`R_quality 0.40 / R_sufficiency 0.25 / R_info_gain 0.20 / R_efficiency 0.15`  
  目的：在过程稳定后，提高终局答案质量权重。  

---

## 6. 可解释性与可面试表达

- 结构化计划 + 状态机 → “流程可解释、可回放”。  
- Validate 评分 → “证据充分性可量化”。  
- GRPO 作用在 Orchestrator → “策略可训练、反馈更短”。
