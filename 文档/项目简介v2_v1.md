# 强化学习驱动的科研问答 Agent

## 一、项目概述

一个面向科研文献检索的多 Agent 问答系统。核心创新是用 GRPO 算法微调 Qwen2.5-7B 作为 OrchestratorAgent，让它学会在检索过程中做出最优决策——什么时候该搜索、什么时候该读全文、什么时候该停下来回答。

- **Memory**：贯穿全流程，OrchestratorAgent 决策时读取，搜索/回答后写入

## 四、强化学习模块

### 4.1 为什么需要 RL？

| 问题 | 没有 RL 的表现 | 有 RL 后的表现 |
|------|---------------|---------------|
| 简单问题 | 走完整流程，搜 4-5 次 | 搜 1 次就回答 |
| 复杂问题 | 搜索不够就硬答 | 判断信息不足，继续搜 |
| 结果够好了 | 还在反复搜 | 及时停止，生成答案 |
| 需要代码 | 不一定能识别 | 准确判断何时调 CodeAgent |

**核心价值**：让 OrchestratorAgent 学会"什么时候该做什么"，减少无效步骤。

### 4.4 奖励函数设计

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│                         奖励函数 R = Q + E + I                              │
│                                                                             │
│   R_total = α·Q(quality) + β·E(efficiency) + γ·I(info_gain)                │
│   超参数: α=1.0, β=0.3, γ=0.2                                              │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   1. 答案质量 Q（任务结束时计算，主要奖励）                                   │
│   ─────────────────────────────────────────────────────────────────────    │
│                                                                             │
│   计算方式：                                                                 │
│   Q = 0.6 × Rouge_L(answer, reference) + 0.4 × LLM_score / 5.0             │
│                                                                             │
│   • Rouge_L：答案与参考答案的文本重叠度                                     │
│   • LLM_score：用 GPT-4 对答案打分（1-5 分）                                │
│                                                                             │
│   示例：                                                                     │
│   - 答案完整准确，覆盖所有要点 → Q ≈ 0.9                                    │
│   - 答案部分正确，遗漏关键信息 → Q ≈ 0.5                                    │
│   - 答案错误或答非所问         → Q ≈ 0.1                                    │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   2. 效率惩罚 E（每步计算，鼓励用更少步骤完成任务）                           │
│   ─────────────────────────────────────────────────────────────────────    │
│                                                                             │
│   每个动作的成本：                                                           │
│   ┌─────────────────────────────────────────────────────────────────────┐  │
│   │  动作                        │  惩罚值   │  理由                     │  │
│   ├─────────────────────────────────────────────────────────────────────┤  │
│   │  调用 OptimizerAgent         │  -0.02   │  消耗 LLM API             │  │
│   │  调用 SelectorAgent          │  -0.02   │  消耗 LLM + Reranker      │  │
│   │  调用 webSearch (Tool)       │  -0.05   │  消耗搜索 API（贵）       │  │
│   │  调用 urlParser (Tool)       │  -0.08   │  全文解析更贵             │  │
│   │  调用 CodeAgent              │  -0.03   │  代码执行有风险           │  │
│   │  调用 AssistantAgent (结束)  │   0.00   │  生成答案不扣分           │  │
│   └─────────────────────────────────────────────────────────────────────┘  │
│                                                                             │
│   效果：模型会倾向于用最少的步骤完成任务                                     │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   3. 信息增益 I（搜索/读全文时计算，鼓励获取新信息）                          │
│   ─────────────────────────────────────────────────────────────────────    │
│                                                                             │
│   计算方式：                                                                 │
│   new_emb = BGE_encode(新获取的文档)                                        │
│   old_emb = BGE_encode(已有的证据)                                          │
│   similarity = cosine_similarity(new_emb, old_emb)                         │
│   I = 1.0 - similarity   # 相似度低 = 新信息多 = 增益高                     │
│                                                                             │
│   示例：                                                                     │
│   - 搜到全新的相关论文           → I ≈ 0.8（奖励）                          │
│   - 搜到和已有内容重复的结果     → I ≈ 0.1（几乎不奖励）                    │
│                                                                             │
│   效果：避免重复搜索相同内容，鼓励探索新方向                                 │
│                                                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   4. 特殊奖励/惩罚                                                           │
│   ─────────────────────────────────────────────────────────────────────    │
│                                                                             │
│   • 缓存命中奖励：+0.1（直接用缓存，省了搜索）                               │
│   • 代码执行成功：+0.1                                                      │
│   • 代码执行失败：-0.05                                                     │
│   • 超时惩罚（>30秒）：-0.3                                                 │
│   • 超过最大步数（10步）：-0.5                                              │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**奖励函数代码示例**：

```python
def compute_reward(state, action, next_state, is_terminal):
    reward = 0.0
    
    # 1. 效率惩罚（每步都有）
    action_cost = {
        "OptimizerAgent": -0.02,
        "SelectorAgent": -0.02,
        "ValidatorAgent": -0.01,
        "ReorchestratorAgent": -0.01,
        "CodeAgent": -0.03,
        "AssistantAgent": 0.0,
        "webSearch": -0.05,
        "urlParser": -0.08,
    }
    reward += action_cost.get(action, 0)
    
    # 2. 信息增益（搜索/读全文时）
    if action in ["webSearch", "urlParser"]:
        new_docs = next_state["new_documents"]
        old_docs = state["evidence"]
        info_gain = 1.0 - cosine_similarity(
            bge_encode(new_docs), 
            bge_encode(old_docs)
        )
        reward += 0.2 * info_gain
    
    # 3. 缓存命中奖励
    if next_state.get("cache_hit"):
        reward += 0.1
    
    # 4. 答案质量（任务结束时）
    if is_terminal:
        answer = next_state["answer"]
        reference = next_state["reference"]
        
        rouge_score = compute_rouge_l(answer, reference)
        llm_score = gpt4_evaluate(answer, state["question"]) / 5.0
        quality = 0.6 * rouge_score + 0.4 * llm_score
        
        reward += 1.0 * quality
    
    return reward
```

**设计思路**：
| 目标 | 对应奖励 | 效果 |
|------|----------|------|
| 答案要好 | Q(quality) | 不会为了省步骤而牺牲质量 |
| 步骤要少 | E(efficiency) | 不会无意义地反复搜索 |
| 信息要新 | I(info_gain) | 不会搜重复内容 |
