## 📚 Part 1: 核心概念（必须先理解）

### 1.1 本项目到底在微调什么？

**一句话总结**：我们用 GRPO 算法训练 Qwen2.5-7B，让它学会"什么时候该搜索、什么时候该深挖、什么时候该停止"。

```
┌────────────────────────────────────────────────────────────┐
│                    训练前 vs 训练后                          │
├────────────────────────────────────────────────────────────┤
│  训练前（原始 Qwen2.5-7B）：                                 │
│    用户问: "BERT 的预训练方法是什么？"                       │
│    模型答: 直接生成答案（可能不准确、没有查资料）             │
│                                                              │
│  训练后（GRPO 微调后）：                                     │
│    用户问: "BERT 的预训练方法是什么？"                       │
│    模型答: "动作: SEARCH                                     │
│            理由: 这是一个技术问题，需要搜索最新资料确认"      │
│    → 执行搜索 → 根据结果决定下一步 → 最终生成准确答案        │
└────────────────────────────────────────────────────────────┘
```

### 1.2 什么是 GRPO？为什么用它？

**GRPO = Group Relative Policy Optimization**，是 DeepSeek 提出的算法。

**与 PPO 的核心区别**（面试必问）：

| 对比 | PPO | GRPO |
|------|-----|------|
| 需要 Critic 网络？ | ✅ 需要（多训练一个网络） | ❌ 不需要 |
| 优势计算方式 | A = Q(s,a) - V(s) | A = (R - 组内平均) / 组内标准差 |
| 参数量 | 2 倍（Policy + Critic） | 1 倍 |
| 适合场景 | 通用 RL | LLM 微调 |

**直观理解 GRPO**：
```
传统 PPO：
  "这个动作的价值是 0.8，平均价值是 0.5，优势 = +0.3"
  → 需要另一个网络估计"平均价值"

GRPO：
  同一个问题让模型生成 4 个不同回答
  回答 A 得分 0.9（最高）→ 增加 A 的概率
  回答 B 得分 0.3（最低）→ 降低 B 的概率
  → 不需要额外网络，直接用组内比较
```

### 1.3 什么是 LoRA？为什么用它？

**LoRA = Low-Rank Adaptation**，一种参数高效微调方法。

**核心思想**：不修改原模型的 70 亿参数，而是插入一些小的"旁路"（约 2000 万参数）。

```
原模型参数: 7,000,000,000 (70亿) → 冻结，不动
LoRA 参数:     20,000,000 (2000万) → 训练这部分
训练参数占比: 0.28%
```

**为什么用 LoRA 而不是全量微调？**

| 方案 | 显存需求 | 训练时间 | 灾难性遗忘风险 |
|------|----------|----------|----------------|
| 全量微调 | ~80GB（需要 A100-80G） | 3-5 天 | 高 |
| LoRA | ~30GB（A100-40G 够用） | 15-20 小时 | 低 |

## 📊 Part 3: 准备训练数据

### 3.1 数据格式说明

GRPO 训练需要的数据格式：

```json
{
  "prompt": "你是一个科研文献检索助手...\n\n【用户问题】BERT 的预训练方法是什么？\n【当前状态】已搜索 0 次...\n\n请选择下一步动作:",
  "chosen": "动作: SEARCH\n理由: 这是一个技术细节问题，需要搜索相关论文确认 MLM 和 NSP 的具体实现方式。",
  "rejected": "动作: ANSWER\n理由: 我知道答案。"
}
```

**三个字段的含义**：
- `prompt`: 状态描述（输入给模型的文本）
- `chosen`: 好的回答（应该增加概率）
- `rejected`: 差的回答（应该降低概率）

### 3.2 数据收集方案

**本项目方案：自动生成 + 人工校验**

```python
# generate_training_data.py
import json
from openai import OpenAI  # 用 DeepSeek API

client = OpenAI(
    api_key="your-deepseek-api-key",
    base_url="https://api.deepseek.com/v1"
)

# 状态模板
STATE_TEMPLATE = """你是一个科研文献检索助手，需要决定下一步动作。

【用户问题】
{query}

【当前状态】
- 已搜索次数: {search_count}
- 已深读文章数: {deep_read_count}
- 当前搜索结果质量: {result_quality}

【已有检索结果摘要】
{results_summary}

【可选动作】
1. SEARCH: 发起新的网络搜索
2. READ_FULL: 深入阅读某篇文章全文
3. REFINE: 优化搜索词后重新搜索
4. ANSWER: 基于已有信息生成最终答案

请选择下一步动作，格式：
动作: <动作名>
理由: <一句话解释>"""

def generate_training_pair(query, state):
    """生成一对 chosen/rejected 数据"""
    prompt = STATE_TEMPLATE.format(
        query=query,
        search_count=state['search_count'],
        deep_read_count=state['deep_read_count'],
        result_quality=state['result_quality'],
        results_summary=state.get('results_summary', '暂无')
    )
    
    # 让 LLM 生成"好的决策"
    good_response = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": "你是决策专家，给出最优的检索决策。"},
            {"role": "user", "content": prompt}
        ],
        temperature=0.3
    ).choices[0].message.content
    
    # 让 LLM 生成"差的决策"
    bad_response = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "system", "content": "你是一个新手，给出不太好的检索决策。"},
            {"role": "user", "content": prompt}
        ],
        temperature=0.9
    ).choices[0].message.content
    
    return {
        "prompt": prompt,
        "chosen": good_response,
        "rejected": bad_response
    }

# 生成数据
queries = [
    "BERT 的预训练方法是什么？",
    "Transformer 的注意力机制怎么计算？",
    "对比 GPT 和 BERT 的区别",
    # ... 更多 query
]

states = [
    {"search_count": 0, "deep_read_count": 0, "result_quality": "无"},
    {"search_count": 1, "deep_read_count": 0, "result_quality": "一般"},
    {"search_count": 2, "deep_read_count": 1, "result_quality": "较好"},
    # ... 更多状态组合
]

training_data = []
for query in queries:
    for state in states:
        pair = generate_training_pair(query, state)
        training_data.append(pair)

# 保存
with open("training_data.json", "w", encoding="utf-8") as f:
    json.dump(training_data, f, ensure_ascii=False, indent=2)

print(f"生成 {len(training_data)} 条训练数据")
```

### 3.3 数据量建议

| 数据集 | 数量 | 用途 |

| 训练集 | 2000-3000 条 | 训练模型 |
| 验证集 | 300 条 | 调参、早停 |
| 测试集 | 200 条 | 最终评估 |

## 🚀 Part 4: GRPO 训练（核心代码）

### 4.1 完整训练脚本

```python
# train_grpo.py
"""
GRPO 训练 Qwen2.5-7B 做决策
运行命令: python train_grpo.py
"""

import os
import torch
import wandb
from datasets import load_dataset
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import GRPOConfig, GRPOTrainer

# ============ 配置参数 ============
MODEL_NAME = "./models/Qwen2.5-7B-Instruct"  # 本地模型路径
OUTPUT_DIR = "./grpo_output"
DATA_PATH = "./training_data.json"

# 训练超参数
EPOCHS = 3
BATCH_SIZE = 2  # 每个 GPU 的 batch size
GRAD_ACCUM = 8  # 梯度累积步数，有效 batch = 2 * 8 = 16
LEARNING_RATE = 1e-5
GROUP_SIZE = 4  # GRPO 每个 prompt 采样几个 response

# LoRA 配置
LORA_R = 16
LORA_ALPHA = 32
LORA_DROPOUT = 0.05

# ============ 初始化 wandb ============
wandb.init(
    project="rl-agent-grpo",
    name="qwen2.5-7b-grpo-v1",
    config={
        "model": MODEL_NAME,
        "epochs": EPOCHS,
        "batch_size": BATCH_SIZE * GRAD_ACCUM,
        "lr": LEARNING_RATE,
        "lora_r": LORA_R,
    }
)

# ============ 加载模型 ============
print("正在加载模型...")
model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    torch_dtype=torch.bfloat16,  # 用 bf16 节省显存
    device_map="auto",
    trust_remote_code=True,
)
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME, trust_remote_code=True)
tokenizer.pad_token = tokenizer.eos_token

# ============ 配置 LoRA ============
print("配置 LoRA...")
lora_config = LoraConfig(
    r=LORA_R,
    lora_alpha=LORA_ALPHA,
    target_modules=[
        "q_proj", "k_proj", "v_proj", "o_proj",  # attention
        "gate_proj", "up_proj", "down_proj"       # FFN
    ],
    lora_dropout=LORA_DROPOUT,
    bias="none",
    task_type="CAUSAL_LM",
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# 输出类似: trainable params: 20,971,520 || all params: 7,615,616,000 || trainable%: 0.28%

# ============ 加载数据 ============
print("加载训练数据...")
dataset = load_dataset("json", data_files=DATA_PATH)["train"]
dataset = dataset.train_test_split(test_size=0.1)
train_dataset = dataset["train"]
eval_dataset = dataset["test"]
print(f"训练集: {len(train_dataset)} 条, 验证集: {len(eval_dataset)} 条")

# ============ 定义 Reward 函数 ============
def reward_function(completions, prompts):
    """
    计算每个 completion 的 reward
    这是 GRPO 的核心！决定了模型学什么
    """
    rewards = []
    for prompt, completion in zip(prompts, completions):
        reward = 0.0
        
        # 1. 解析动作
        action = None
        if "动作: SEARCH" in completion or "动作:SEARCH" in completion:
            action = "SEARCH"
        elif "动作: READ_FULL" in completion:
            action = "READ_FULL"
        elif "动作: REFINE" in completion:
            action = "REFINE"
        elif "动作: ANSWER" in completion:
            action = "ANSWER"
        
        if action is None:
            reward = -0.5  # 格式不对，惩罚
            rewards.append(reward)
            continue
        
        # 2. 根据状态判断动作是否合理
        search_count = 0
        if "已搜索次数: " in prompt:
            try:
                search_count = int(prompt.split("已搜索次数: ")[1].split("\n")[0])
            except:
                pass
        
        result_quality = "无"
        if "当前搜索结果质量: " in prompt:
            result_quality = prompt.split("当前搜索结果质量: ")[1].split("\n")[0]
        
        # 规则奖励
        if action == "SEARCH":
            if search_count < 2:
                reward += 0.3  # 早期搜索是好的
            else:
                reward -= 0.1  # 搜索太多次扣分
        
        elif action == "ANSWER":
            if search_count >= 1 and result_quality in ["较好", "好"]:
                reward += 0.5  # 有好结果时回答
            elif search_count == 0:
                reward -= 0.5  # 没搜就答，扣分
        
        elif action == "READ_FULL":
            if result_quality in ["一般", "较好"]:
                reward += 0.3  # 有结果时深读
            else:
                reward -= 0.2  # 没结果瞎读
        
        elif action == "REFINE":
            if search_count >= 1 and result_quality in ["差", "一般"]:
                reward += 0.3  # 结果不好时优化
            else:
                reward -= 0.1
        
        # 3. 理由质量（简单判断：理由够长说明有思考）
        if "理由:" in completion:
            reason = completion.split("理由:")[1].strip()
            if len(reason) > 20:
                reward += 0.1
        
        rewards.append(reward)
    
    return rewards

# ============ 配置 Trainer ============
print("配置 GRPO Trainer...")
grpo_config = GRPOConfig(
    output_dir=OUTPUT_DIR,
    num_train_epochs=EPOCHS,
    per_device_train_batch_size=BATCH_SIZE,
    gradient_accumulation_steps=GRAD_ACCUM,
    learning_rate=LEARNING_RATE,
    num_generations=GROUP_SIZE,  # GRPO group size
    max_completion_length=128,   # 回答最长 128 token
    max_prompt_length=1024,      # 状态描述最长 1024 token
    logging_steps=10,
    save_steps=500,
    eval_steps=500,
    bf16=True,
    remove_unused_columns=False,
    report_to="wandb",
)

trainer = GRPOTrainer(
    model=model,
    config=grpo_config,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    tokenizer=tokenizer,
    reward_funcs=reward_function,
)

# ============ 开始训练 ============
print("开始训练！预计 15-20 小时...")
print("可以在 wandb.ai 查看训练曲线")
trainer.train()

# ============ 保存模型 ============
print("保存模型...")
trainer.save_model(f"{OUTPUT_DIR}/final")
tokenizer.save_pretrained(f"{OUTPUT_DIR}/final")
print(f"模型已保存到 {OUTPUT_DIR}/final")

wandb.finish()
print("训练完成！")
```

## 🔧 Part 5: 常见问题与解决方案

### 5.1 显存不足（OOM）

**报错信息**：
```
torch.cuda.OutOfMemoryError: CUDA out of memory. Tried to allocate 2.00 GiB
```

**解决方案**：

```python
# 方案 1：减小 batch size
BATCH_SIZE = 1  # 从 2 改成 1
GRAD_ACCUM = 16  # 相应增加梯度累积

# 方案 2：减小模型精度
model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    torch_dtype=torch.float16,  # 从 bf16 改成 fp16（省一点）
    load_in_8bit=True,          # 或者用 8bit 量化（省更多）
    device_map="auto",
)

# 方案 3：减小序列长度
max_prompt_length=512,   # 从 1024 改成 512
max_completion_length=64,  # 从 128 改成 64

# 方案 4：启用梯度检查点（用时间换空间）
model.gradient_checkpointing_enable()
```

### 5.2 训练不收敛（Loss 不下降）

**可能原因和解决方案**：

| 现象 | 可能原因 | 解决方案 |
|------|----------|----------|
| Loss 卡在 0.6+ 不动 | 学习率太小 | lr 从 1e-5 调到 5e-5 |
| Loss 震荡剧烈 | 学习率太大 | lr 从 1e-5 调到 5e-6 |
| Loss 下降后又上升 | 过拟合 | 加 early stopping |
| Reward 一直是负数 | Reward 函数有 bug | 打印检查 reward 计算 |

**调试技巧**：
```python
# 在 reward_function 里加打印
def reward_function(completions, prompts):
    rewards = []
    for i, (prompt, completion) in enumerate(zip(prompts, completions)):
        reward = compute_reward(...)
        
        # 每 100 个样本打印一次
        if i % 100 == 0:
            print(f"[Debug] completion: {completion[:100]}...")
            print(f"[Debug] reward: {reward}")
        
        rewards.append(reward)
    return rewards
```

### 5.3 策略坍塌（模型只输出同一个动作）

**现象**：模型永远输出 "动作: SEARCH"，不管状态是什么。

**解决方案**：

## 📊 Part 6: 奖励函数设计详解

### 6.1 本项目的奖励函数

参考 项目简介v2.md 中的公式：

$$R = \alpha \cdot Q + \beta \cdot E + \gamma \cdot I$$

| 符号 | 含义 | 权重 | 计算方式 |
|------|------|------|----------|
| $Q$ | 质量奖励 | α=1.0 | 答案准确性、完整性 |
| $E$ | 效率奖励 | β=0.3 | 步数少、缓存命中 |
| $I$ | 信息增益 | γ=0.2 | 新信息的价值 |

### 6.2 完整的 Reward 函数实现

```python
def compute_reward(state, action, result, final_answer=None, user_feedback=None):
    """
    综合奖励计算
    
    Args:
        state: 当前状态 dict
        action: 执行的动作 str
        result: 动作执行结果 dict
        final_answer: 最终答案（如果是 ANSWER 动作）
        user_feedback: 用户反馈（'positive'/'negative'/None）
    
    Returns:
        float: 奖励值，通常在 [-1, 1] 范围
    """
    
    # ===== 1. 质量奖励 Q (权重 1.0) =====
    quality_reward = 0.0
    
    # 用户直接反馈（最可靠）
    if user_feedback == 'positive':
        quality_reward = 1.0
    elif user_feedback == 'negative':
        quality_reward = -0.5
    
    # 中间步骤的质量（当没有用户反馈时）
    elif action == "SEARCH":
        # 搜到高质量结果
        if result.get('hits') and result['hits'][0].get('score', 0) > 0.7:
            quality_reward = 0.3
        elif result.get('hits'):
            quality_reward = 0.1
        else:
            quality_reward = -0.1  # 搜不到东西
    
    elif action == "READ_FULL":
        # 深读后提取到有用信息
        if result.get('extracted_info') and len(result['extracted_info']) > 100:
            quality_reward = 0.3
        else:
            quality_reward = 0.0
    
    elif action == "ANSWER":
        # 如果没有用户反馈，用 LLM 自评（可选）
        if final_answer and not user_feedback:
            # quality_reward = llm_evaluate_answer(state['query'], final_answer)
            quality_reward = 0.2  # 简单起见，给个默认分
    
    # ===== 2. 效率奖励 E (权重 0.3) =====
    efficiency_reward = 0.0
    
    # 搜索成本惩罚
    search_count = state.get('search_count', 0)
    efficiency_reward -= 0.05 * search_count  # 每次搜索扣 0.05
    
    # 缓存命中奖励
    if result.get('cache_hit'):
        efficiency_reward += 0.2  # 缓存命中，省了 API 调用
    
    # 时间惩罚（可选）
    elapsed = state.get('elapsed_time', 0)
    if elapsed > 30:  # 超过 30 秒
        efficiency_reward -= 0.1
    
    # ===== 3. 信息增益 I (权重 0.2) =====
    info_gain_reward = 0.0
    
    # 新覆盖的关键词
    prev_keywords = set(state.get('covered_keywords', []))
    new_keywords = set(result.get('new_keywords', []))
    newly_covered = new_keywords - prev_keywords
    info_gain_reward += 0.1 * min(len(newly_covered), 3)  # 每个新关键词 +0.1，最多 3 个
    
    # ===== 加权求和 =====
    alpha, beta, gamma = 1.0, 0.3, 0.2
    total_reward = alpha * quality_reward + beta * efficiency_reward + gamma * info_gain_reward
    
    # 限制范围（可选）
    total_reward = max(-1.0, min(1.0, total_reward))
    
    return total_reward
```

### 6.3 奖励塑形技巧

```python
def shaped_reward(state, action, next_state, base_reward):
    """
    奖励塑形：引导模型学习更快
    """
    shaping = 0.0
    
    # 1. 早期鼓励探索
    if state['search_count'] < 2 and action == 'SEARCH':
        shaping += 0.1  # 前两次搜索给额外奖励
    
    # 2. 后期鼓励收敛
    if state['search_count'] >= 3 and action == 'ANSWER':
        shaping += 0.1  # 搜了 3 次后回答，给奖励
    
    # 3. 惩罚重复动作
    if action == state.get('last_action'):
        shaping -= 0.1  # 连续执行相同动作，扣分
    
    # 4. 惩罚死循环（SEARCH → SEARCH → SEARCH...）
    if state.get('action_history', [])[-3:] == ['SEARCH', 'SEARCH', 'SEARCH']:
        shaping -= 0.3
    
    return base_reward + shaping
```

### 基础概念题（Q1-Q8）

#### Q1: 解释一下 GRPO 和 PPO 的区别，为什么本项目选择 GRPO？

**参考答案**：

**核心区别在于优势（Advantage）估计方法**：

| 方面 | PPO | GRPO |
|------|-----|------|
| **Advantage 计算** | $A = Q(s,a) - V(s)$ | $A = \frac{R - \mu_{group}}{\sigma_{group}}$ |
| **需要 Critic 网络** | ✅ 需要额外训练一个价值网络 | ❌ 不需要 |
| **参数量** | 2 倍（Policy + Critic） | 1 倍（只有 Policy） |
| **显存需求** | ~60GB | ~30GB |

**GRPO 的直观理解**：
```
PPO 的做法：
  "这个动作价值 0.8，平均价值 0.5，优势 = +0.3"
  → 需要另一个网络估计"平均价值是多少"

GRPO 的做法：
  同一个 prompt 让模型生成 4 个回答
  回答 A 得 0.9 分（组内最高）→ 增加 A 的概率
  回答 D 得 0.2 分（组内最低）→ 降低 D 的概率
  → 不需要额外网络，直接组内比较
```

**选择 GRPO 的原因**：
1. **省资源**：不需要 Critic 网络，A100-40G 就能跑
2. **与 LLM 原生兼容**：GRPO 是 DeepSeek 专门为 LLM 微调设计的
3. **实现简单**：trl 库几行代码搞定
4. **热门方向**：DeepSeek-R1 用的就是类似思路，面试加分

#### Q2: 什么是 LoRA？为什么用 LoRA 而不是全量微调？

**参考答案**：

**LoRA = Low-Rank Adaptation（低秩适应）**

**核心思想**：
```
原始权重矩阵 W (d × d) → 冻结不动
插入两个小矩阵 A (d × r) 和 B (r × d)
输出 = W·x + A·B·x

其中 r << d（比如 r=16，d=4096）
训练时只更新 A 和 B
```

**参数量对比**：
```
全量微调: 7,000,000,000 参数全部训练
LoRA:        20,000,000 参数（0.28%）
```

**为什么用 LoRA**：

| 对比 | 全量微调 | LoRA |
|------|----------|------|
| 显存需求 | ~80GB（需要 A100-80G） | ~30GB（A100-40G 够用） |
| 训练时间 | 3-5 天 | 15-20 小时 |
| 灾难性遗忘 | 风险高 | 风险低（原模型冻结） |
| 多任务切换 | 需要多份完整模型 | 只需切换 LoRA 权重 |

**本项目配置**：
```python
LoraConfig(
    r=16,           # 秩，越大容量越大
    lora_alpha=32,  # 缩放系数，通常设为 2×r
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],  # 应用到 attention 层
)
```

#### Q3: LoRA 的 r 和 alpha 参数怎么选？

**参考答案**：

| 参数 | 含义 | 本项目值 | 调参建议 |
|------|------|----------|----------|
| `r` | 低秩分解的秩 | 16 | 8-64，越大容量越大 |
| `alpha` | 缩放系数 | 32 | 通常设为 2×r |
| `dropout` | 防过拟合 | 0.05 | 0-0.1 |

**r 的选择经验**：
- `r=8`: 轻量级，适合简单任务
- `r=16`: 平衡点，**多数场景推荐**
- `r=32+`: 容量大，适合复杂任务

**alpha/r 比例的意义**：
```
实际缩放 = alpha / r
alpha=32, r=16 → 缩放因子 = 2
alpha=16, r=16 → 缩放因子 = 1

缩放因子越大，LoRA 的影响越大
经验值：alpha/r = 2 效果最稳定
```

#### Q6: 奖励函数是如何设计的？

**参考答案**：

**公式**：$R = \alpha \cdot Q + \beta \cdot E + \gamma \cdot I$

| 符号 | 含义 | 权重 | 计算方式 |
|------|------|------|----------|
| $Q$ | 质量 | α=1.0 | 用户反馈、答案准确性 |
| $E$ | 效率 | β=0.3 | 步数惩罚、缓存命中奖励 |
| $I$ | 信息增益 | γ=0.2 | 新覆盖的关键词数量 |

**具体实现**：
```python
# 质量奖励
if user_feedback == 'positive': Q = 1.0
elif user_feedback == 'negative': Q = -0.5
elif action == 'SEARCH' and got_good_results: Q = 0.3

# 效率奖励（惩罚）
E = -0.05 * search_count  # 每次搜索扣 0.05
if cache_hit: E += 0.2    # 缓存命中加 0.2

# 信息增益
I = 0.1 * len(newly_covered_keywords)  # 每个新关键词 +0.1
```

**为什么这样设计**：
- 质量权重最高（1.0）：核心目标是答案质量
- 效率权重适中（0.3）：控制成本但不能太激进
- 信息增益权重最低（0.2）：辅助指标

#### Q7: 什么是奖励塑形（Reward Shaping）？本项目怎么用的？

**参考答案**：

**定义**：在稀疏奖励的基础上，添加中间步骤的奖励信号，引导模型更快学习。

**问题**：如果只有最终用户反馈有奖励，中间步骤都是 0，模型很难学。

**本项目的 Shaping 策略**：

```python
def shaped_reward(state, action, base_reward):
    shaping = 0.0
    
    # 1. 早期鼓励搜索
    if state['search_count'] < 2 and action == 'SEARCH':
        shaping += 0.1  # 前两次搜索额外奖励
    
    # 2. 后期鼓励收敛
    if state['search_count'] >= 3 and action == 'ANSWER':
        shaping += 0.1  # 搜了 3 次后回答，给奖励
    
    # 3. 惩罚重复动作
    if action == state['last_action']:
        shaping -= 0.1  # 连续相同动作扣分
    
    # 4. 惩罚死循环
    if recent_actions == ['SEARCH', 'SEARCH', 'SEARCH']:
        shaping -= 0.3
    
    return base_reward + shaping
```

**注意**：Shaping 奖励不能太大，否则会主导学习，导致模型"钻空子"。

#### Q8: GRPO 的 group_size 设为多少合适？

**参考答案**：

**推荐值：4-8**

| Group Size | 优势估计方差 | 计算成本 | 推荐场景 |
|------------|-------------|----------|----------|
| 2 | 高（不稳定） | 低 | ❌ 不推荐 |
| 4 | 中 | 中 | ✅ 资源受限时 |
| **8** | **低** | **中** | ✅ **推荐** |
| 16 | 很低 | 高 | 追求稳定时 |

**太小的问题**：
```
group_size=2，两个样本奖励 [0.3, 0.5]
mean=0.4, std=0.14
advantages = [-0.71, 0.71]  ← 方差大，估计不准
```

**太大的问题**：
- 每个状态要采样 16 次，显存和时间成本高
- 可能过拟合到特定的回答模式

#### Q20: 如何处理奖励稀疏问题？

**参考答案**：

**问题**：只有最终用户反馈有奖励，中间步骤大部分是 0。

**解决方案**：

```python
# 1. 奖励塑形（前面讲过）
shaped_reward = base_reward + shaping

# 2. 逆向奖励传播
def backward_propagate(trajectory, final_reward, gamma=0.95):
    """把最终奖励按折扣传给前序步骤"""
    discounted = final_reward
    for step in reversed(trajectory):
        step['reward'] += discounted
        discounted *= gamma

# 3. 中间步骤自动评估
def auto_evaluate_step(state, action, result):
    if action == "SEARCH" and len(result['hits']) > 0:
        return 0.1  # 搜到东西给点分
    if action == "READ_FULL" and result.get('info'):
        return 0.1  # 读到信息给点分
    return 0.0
```

## 🔬 Part 11: Loss 函数与训练曲线分析

### 11.1 GRPO 的 Loss 函数

**GRPO Loss 公式**：

$$\mathcal{L}_{GRPO} = -\mathbb{E}_{(s,a) \sim \pi_\theta} \left[ \hat{A}(s,a) \cdot \log \pi_\theta(a|s) \right] - \beta \cdot H(\pi_\theta)$$

**各项含义**：

| 符号 | 含义 | 作用 |
|------|------|------|
| $\hat{A}(s,a)$ | 优势估计（组内相对排名） | 好动作增加概率，差动作降低概率 |
| $\log \pi_\theta(a\|s)$ | 动作的对数概率 | 模型对该动作的置信度 |
| $H(\pi_\theta)$ | 策略熵 | 防止策略坍塌，鼓励探索 |
| $\beta$ | 熵系数 | 控制探索程度，通常 0.01-0.05 |

**直观理解**：

```
假设同一个状态采样 4 个动作，奖励分别是 [0.2, 0.8, 0.5, 0.3]

1. 计算组内优势：
   mean = 0.45, std = 0.24
   advantages = [-1.04, +1.46, +0.21, -0.62]
   
2. 更新策略：
   动作 B (优势 +1.46) → 增加概率 → loss 贡献为负
   动作 A (优势 -1.04) → 降低概率 → loss 贡献为正
   
3. 总 loss = 正贡献 + 负贡献
   如果好动作的概率本来就高 → loss 小
   如果好动作的概率很低 → loss 大（需要大幅调整）
```

### 11.2 Loss 的组成部分

**trl 库中 GRPO 训练会输出多个 loss**：

```

```

|------|----------|------|
| `loss` | 0.2 - 0.8 | 总损失，应该逐渐下降 |
| `policy_loss` | 同上 | 策略梯度部分 |
| `entropy` | 0.5 - 2.0 | 策略多样性，太低=坍塌 |
| `reward/mean` | 逐渐上升 | 平均奖励，核心指标 |
| `kl` | < 0.1 | 新旧策略差异，太大不稳定 |

### 11.5 监控代码实现

```python
# training_monitor.py
import wandb
import numpy as np
from collections import deque

class TrainingMonitor:
    def __init__(self, window_size=100):
        self.loss_history = deque(maxlen=window_size)
        self.reward_history = deque(maxlen=window_size)
        self.entropy_history = deque(maxlen=window_size)
        self.alerts = []
    
    def log(self, metrics):
        """每个 step 调用"""
        self.loss_history.append(metrics.get('loss', 0))
        self.reward_history.append(metrics.get('reward/mean', 0))
        self.entropy_history.append(metrics.get('entropy', 1))
        
        # 异常检测
        self._check_anomalies()
        
        # 上报 wandb
        wandb.log(metrics)
    
    def _check_anomalies(self):
        if len(self.loss_history) < 50:
            return
        
        # 检查 1: Loss 不下降
        recent_loss = list(self.loss_history)[-20:]
        early_loss = list(self.loss_history)[:20]
        if np.mean(recent_loss) >= np.mean(early_loss) * 0.95:
            self._alert("⚠️ Loss 停滞不下降，考虑调大学习率")
        
        # 检查 2: Loss 震荡
        if np.std(recent_loss) > 0.2:
            self._alert("⚠️ Loss 震荡剧烈，考虑调小学习率")
        
        # 检查 3: Entropy 太低
        if np.mean(list(self.entropy_history)[-20:]) < 0.3:
            self._alert("🚨 Entropy 过低，策略可能坍塌！")
        
        # 检查 4: Reward 不上升
        recent_reward = list(self.reward_history)[-20:]
        early_reward = list(self.reward_history)[:20]
        if len(early_reward) > 10 and np.mean(recent_reward) <= np.mean(early_reward):
            self._alert("⚠️ Reward 没有提升，检查 reward 函数")
    
    def _alert(self, message):
        if message not in self.alerts[-5:] if self.alerts else True:
            print(f"\n{message}\n")
            self.alerts.append(message)
            wandb.alert(title="Training Alert", text=message)

# 使用
monitor = TrainingMonitor()

# 在 training loop 中
for step, batch in enumerate(train_loader):
    loss, metrics = train_step(batch)
    monitor.log({
        'loss': loss,
        'reward/mean': metrics['reward_mean'],
        'entropy': metrics['entropy'],
        'step': step,
    })
```

### 11.6 Loss 相关的面试题补充

#### Q31: GRPO 的 Loss 函数是什么？和 PPO 有什么区别？

**参考答案**：

**GRPO Loss**：
$$\mathcal{L} = -\mathbb{E}\left[ \hat{A} \cdot \log \pi_\theta(a|s) \right] - \beta H(\pi)$$

**PPO Loss**：
$$\mathcal{L} = -\mathbb{E}\left[ \min(r_t(\theta) \hat{A}, \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \hat{A}) \right]$$

**核心区别**：

| 方面 | GRPO | PPO |
|------|------|-----|
| Advantage 计算 | 组内相对排名 | 需要 Critic 网络 |
| Clip 机制 | 无 | 有（限制更新幅度） |
| 稳定性 | 依赖 group size | 依赖 clip ratio |

---

#### Q32: 如何从 Loss 曲线判断训练状态？

**参考答案**：

| Loss 曲线形状 | 含义 | 处理方法 |
|---------------|------|----------|
| 稳定下降 → 收敛 | ✅ 健康 | 继续/早停 |
| 一直平的 | 没在学习 | 调大 lr |
| 剧烈震荡 | 不稳定 | 调小 lr |
| 下降后上升 | 过拟合 | early stopping |
| 突然飙升 | 梯度爆炸 | 梯度裁剪 |

**组合判断**：
```
Loss ↓ + Reward ↑ + Entropy 稳定 = 完美训练
Loss ↓ + Reward ↑ + Entropy ↓↓ = 在学但可能坍塌
Loss 平 + Reward 平 = 没在学习
Loss ↓ + Reward 平 = 可能在拟合噪声
```

#### Q33: Entropy 为什么重要？太高或太低分别说明什么？

**参考答案**：

**Entropy（熵）衡量策略的随机性**：
- 高熵 = 动作分布均匀 = 随机探索
- 低熵 = 动作分布集中 = 确定性策略

**理想范围：0.5 - 1.5**

| Entropy 值 | 状态 | 问题 | 解决 |
|------------|------|------|------|
| > 2.0 | 过于随机 | 没学到策略 | 检查 reward |
| 0.8-1.5 | ✅ 健康 | - | - |
| 0.3-0.8 | 偏低 | 可能欠探索 | 观察 |
| < 0.3 | 🚨 坍塌 | 只输出一个动作 | 紧急处理 |

**症状**：

- Loss 突然飙升到很大的值
