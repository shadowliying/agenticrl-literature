## 📚 Part 1: 知识点解析

### 1.1 为什么数据与评估很重要？

**面试官最常问的问题**：
- "你的数据是哪来的？"
- "怎么证明 RL 有用？"
- "评估指标怎么设计的？"

**核心认知**：
| 常见误区 | 正确做法 |
|----------|----------|
| 训练数据和评估数据混用 | 必须完全分开，否则数据泄露 |
| 只看一个指标 | 多维度评估（质量+效率+成本） |
| 只和自己比 | 必须有基线对比 |
| 主观评价 | 尽量用客观指标 + 人工评估补充 |

**为什么必须分开？**

| 错误做法 | 后果 |
|----------|------|
| 用同一批数据训练和评估 | 数据泄露，评估结果虚高 |
| RL 训练用 800 条，再用这 800 条评估系统 | 策略"背答案"，不是真正学会决策 |
| 测试集在调参过程中被看过 | 测试集"泄露"，结果不可信 |

```
┌─────────────────────────────────────────────────────────────────┐
│                        四大评估维度                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   维度 1: 任务完成质量                                           │
│   ════════════════════════════════════════                      │
│                                                                 │
│   • 任务完成率 (Completion Rate)                                │
│     定义: 成功回答问题的比例                                     │
│     计算: 成功数 / 总查询数                                      │
│     目标: > 75%                                                 │
│                                                                 │
│   • 答案准确率 (Answer Accuracy)                                │
│     定义: 答案覆盖关键点的比例                                   │
│     计算: 命中关键点数 / 总关键点数                              │
│     目标: > 80%                                                 │
│                                                                 │
│   • ROUGE-L 分数                                                │
│     定义: 与参考答案的文本相似度                                 │
│     目标: > 0.4                                                 │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   维度 2: 检索效果                                               │
│   ════════════════════════════════════════                      │
│                                                                 │
│   • Top-5 命中率 (Hit@5)                                        │
│     定义: 正确来源出现在 Top-5 结果中的比例                      │
│     计算: Top-5 包含正确来源的查询数 / 总查询数                  │
│     目标: > 80%                                                 │
│                                                                 │
│   • MRR (Mean Reciprocal Rank)                                  │
│     定义: 第一个正确结果排名的倒数的平均                         │
│     计算: (1/rank_1 + 1/rank_2 + ...) / N                       │
│     目标: > 0.6                                                 │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   维度 3: 效率指标                                               │
│   ════════════════════════════════════════                      │
│                                                                 │
│   • 平均搜索次数                                                 │
│     定义: 每个查询调用搜索 API 的次数                            │
│     目标: < 3 次                                                │
│                                                                 │
│   • 平均步骤数                                                   │
│     定义: 每个查询的 Agent 调用总数                              │
│     目标: < 5 步                                                │
│                                                                 │
│   • 响应时间 (Latency)                                          │
│     定义: 从收到问题到返回答案的时间                             │
│     目标: < 30 秒（P95）                                        │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   维度 4: 成本指标                                               │
│   ════════════════════════════════════════                      │
│                                                                 │
│   • API 调用成本                                                 │
│     计算: 搜索 API 费用 + LLM API 费用                           │
│     目标: < ¥0.1 / 查询                                         │
│                                                                 │
│   • 缓存命中率                                                   │
│     定义: 从缓存复用结果的比例                                   │
│     计算: 缓存命中数 / 总搜索请求数                              │
```

```python
# data_collection/generate_queries.py
"""
Step 1: 用 LLM 生成科研检索问题
"""

import json
from openai import OpenAI

client = OpenAI(
    api_key="your-deepseek-api-key",
    base_url="https://api.deepseek.com/v1"
)

GENERATION_PROMPT = """请生成 10 个关于 {domain} 领域的科研检索问题。

要求：
1. 难度从简单到复杂
2. 类型多样：事实问答、原理解释、对比分析、代码请求、综述类
3. 问题要具体，不要太宽泛

输出格式（JSON 数组）：
[
  {{"query": "问题1", "type": "事实问答", "difficulty": "简单"}},
  {{"query": "问题2", "type": "原理解释", "difficulty": "中等"}},
  ...
]
"""

DOMAINS = [
    "深度学习基础（CNN、RNN、Transformer）",
    "预训练语言模型（BERT、GPT、LLaMA）",
    "计算机视觉（目标检测、图像分割）",
    "强化学习（DQN、PPO、GRPO）",
    "大语言模型应用（RAG、Agent、微调）",
]

def generate_queries(domain, num_batches=10):
    """为某个领域生成问题"""
    all_queries = []
    
    for i in range(num_batches):
        response = client.chat.completions.create(
            model="deepseek-chat",
            messages=[
                {"role": "user", "content": GENERATION_PROMPT.format(domain=domain)}
            ],
            temperature=0.8,  # 增加多样性
        )
        
        try:
            queries = json.loads(response.choices[0].message.content)
            all_queries.extend(queries)
            print(f"[{domain}] Batch {i+1}: 生成 {len(queries)} 条")
        except json.JSONDecodeError:
            print(f"[{domain}] Batch {i+1}: 解析失败，跳过")
    
    return all_queries

# 生成所有领域的问题
all_data = []
for domain in DOMAINS:
    queries = generate_queries(domain, num_batches=10)
    all_data.extend(queries)

print(f"\n总共生成 {len(all_data)} 条问题")

# 保存
with open("raw_queries.json", "w", encoding="utf-8") as f:
    json.dump(all_data, f, ensure_ascii=False, indent=2)
```

```python
# data_collection/augment_queries.py
"""
Step 2: Query 改写增强
"""

REWRITE_PROMPT = """将以下问题改写成 3 种不同的问法，保持语义相同但表达不同：

原问题：{query}

要求：
1. 改变句式（疑问句/陈述句/祈使句）
2. 改变用词（同义词替换）
3. 改变详细程度（更具体/更概括）

输出格式（JSON 数组）：
["改写1", "改写2", "改写3"]
"""

def augment_query(query):
    """对单个 query 进行改写"""
    response = client.chat.completions.create(
        model="deepseek-chat",
        messages=[
            {"role": "user", "content": REWRITE_PROMPT.format(query=query)}
        ],
        temperature=0.7,
    )
    
    try:
        rewrites = json.loads(response.choices[0].message.content)
        return [query] + rewrites  # 原始 + 3 个改写
    except:
        return [query]

# 对 25% 的数据进行改写
import random
to_augment = random.sample(all_data, len(all_data) // 4)

augmented = []
for item in to_augment:
    variants = augment_query(item["query"])
    for v in variants:
        augmented.append({
            "query": v,
            "type": item["type"],
            "difficulty": item["difficulty"],
            "original": item["query"]
        })

print(f"改写增强后: {len(augmented)} 条")
```

```python
"""
Step 3: 收集决策轨迹（用于 RL 训练）
"""

import time
from system import DeepResearchSystem  # 你的系统

def collect_trajectory(query, system):
    """
    运行系统，收集完整的决策轨迹
    """
    trajectory = []
    
    # 初始化状态
    state = {
        "query": query,
        "search_count": 0,
        "result_quality": "无",
        "evidence": [],
        "cache_hit": False,
    }
    
    # 运行系统
    system.reset()
    done = False
    step = 0
    
    while not done and step < 10:
        step += 1
        
        # OrchestratorAgent 决策
        action = system.orchestrator.decide(state)
        
        # 执行动作
        result = system.execute(action)
        
        # 计算 reward
        reward = compute_reward(state, action, result)
        
        # 更新状态
        next_state = update_state(state, action, result)
        
        # 记录
        trajectory.append({
            "step": step,
            "state": state.copy(),
            "action": action,
            "action_output": result.get("output", ""),
            "reward": reward,
        })
        
        # 判断是否结束
        done = (action == "AssistantAgent" and result.get("success"))
        state = next_state
    
    return {
        "query": query,
        "trajectory": trajectory,
        "total_reward": sum(t["reward"] for t in trajectory),
        "total_steps": len(trajectory),
        "success": done,
    }

def compute_reward(state, action, result):
    """计算单步奖励"""
    reward = 0.0
    
    # 效率惩罚
    action_cost = {
        "OptimizerAgent": -0.02,
        "SelectorAgent": -0.02,
        "ValidatorAgent": -0.01,
        "webSearch": -0.05,
        "urlParser": -0.08,
        "AssistantAgent": 0.0,
    }
    reward += action_cost.get(action, 0)
    
    # 信息增益
    if action in ["webSearch", "urlParser"]:
        if result.get("new_info"):
            reward += 0.2
    
    # 缓存命中
    if result.get("cache_hit"):
        reward += 0.1
    
    # 最终质量
    if action == "AssistantAgent" and result.get("success"):
        reward += 0.8
    
    return reward

# 收集轨迹
system = DeepResearchSystem()
training_data = []

for item in training_queries:  # 2000 条训练 query

    print(f"收集 {len(training_data)}/{len(training_queries)}: "
          f"steps={traj['total_steps']}, reward={traj['total_reward']:.2f}")

# 保存
with open("rl_training_data.json", "w", encoding="utf-8") as f:
```

```python
import json

class SystemEvaluator:
    def __init__(self, system, eval_data_path):
        self.system = system

    def load_eval_data(self, path):
        with open(path, 'r', encoding='utf-8') as f:
            return json.load(f)
    
    def evaluate_single(self, item):
        """评估单个查询"""
        query = item["query"]
        reference = item["reference_answer"]
        key_points = item["key_points"]
        expected_sources = item.get("expected_sources", [])
        
        # 运行系统
        start_time = time.time()
        result = self.system.run(query)
        latency = time.time() - start_time
        
        # 计算指标
        metrics = {}
        
        # 1. 是否成功
        metrics["success"] = result.get("success", False)
        
        # 2. ROUGE-L
        if result.get("answer"):
            rouge = self.rouge_scorer.score(reference, result["answer"])
            metrics["rouge_l"] = rouge['rougeL'].fmeasure
        else:
            metrics["rouge_l"] = 0.0
        
        # 3. 关键点命中
        answer = result.get("answer", "").lower()
        hits = sum(1 for kp in key_points if kp.lower() in answer)
        metrics["key_point_coverage"] = hits / len(key_points) if key_points else 0
        
        # 4. 来源命中 (Top-5)
        sources = result.get("sources", [])[:5]
        source_hit = any(exp in str(sources) for exp in expected_sources)
        metrics["source_hit_at_5"] = 1 if source_hit else 0
        
        # 5. 效率指标
        metrics["search_count"] = result.get("search_count", 0)
        metrics["total_steps"] = result.get("total_steps", 0)
        metrics["latency"] = latency
        
        # 6. 成本
        metrics["api_cost"] = result.get("api_cost", 0)
        metrics["token_count"] = result.get("token_count", 0)
        metrics["cache_hit"] = result.get("cache_hit", False)
        
        return metrics
    
    def evaluate_all(self):
        """评估所有数据"""
        print(f"开始评估 {len(self.eval_data)} 条数据...")
        
        for i, item in enumerate(self.eval_data):
            try:
                metrics = self.evaluate_single(item)
                for k, v in metrics.items():
                    self.metrics[k].append(v)
                
                if (i + 1) % 50 == 0:
                    print(f"进度: {i+1}/{len(self.eval_data)}")
            except Exception as e:
                print(f"评估失败 [{i}]: {e}")
        
        return self.compute_summary()
    
    def compute_summary(self):
        """计算汇总指标"""
        summary = {}
        
        # 完成率
        summary["completion_rate"] = np.mean(self.metrics["success"])
        
        # 质量指标
        summary["avg_rouge_l"] = np.mean(self.metrics["rouge_l"])
        summary["avg_key_point_coverage"] = np.mean(self.metrics["key_point_coverage"])
        
        # 检索效果
        summary["hit_at_5"] = np.mean(self.metrics["source_hit_at_5"])
        
        # 效率指标
        summary["avg_search_count"] = np.mean(self.metrics["search_count"])
        summary["avg_steps"] = np.mean(self.metrics["total_steps"])
        summary["avg_latency"] = np.mean(self.metrics["latency"])
        summary["p95_latency"] = np.percentile(self.metrics["latency"], 95)
        
        # 成本指标
        summary["avg_api_cost"] = np.mean(self.metrics["api_cost"])
        summary["avg_tokens"] = np.mean(self.metrics["token_count"])
        summary["cache_hit_rate"] = np.mean(self.metrics["cache_hit"])
        
        return summary

print("评估结果")

    if isinstance(v, float):
        print(f"{k}: {v:.4f}")
    else:
```

#### Q10: ROUGE-L 是什么？为什么用它？

**参考答案**：

**ROUGE-L**：基于最长公共子序列（LCS）的文本相似度指标。

**计算方式**：
```
ROUGE-L = LCS(answer, reference) / len(reference)

LCS = 最长公共子序列
answer = 系统生成的答案
reference = 参考答案
```

**为什么用 ROUGE-L**：
1. **适合长文本**：不要求完全匹配，允许词序变化
2. **标准化**：NLP 领域广泛使用，结果可比较
3. **简单可靠**：不需要额外模型

**局限性**：
- 不能判断语义是否正确（只看词重叠）
- 所以还要配合人工评估和关键点覆盖率

#### Q11: 人工评估怎么做的？

**参考答案**：

**抽样评估**：从 800 条测试集中随机抽 50 条。

**评估维度**（1-5 分）：

| 维度 | 说明 | 评分标准 |
|------|------|----------|
| 准确性 | 答案是否事实正确 | 1=错误，5=正确 |
| 完整性 | 是否覆盖所有方面 | 1=遗漏，5=全面 |
| 相关性 | 是否切题 | 1=跑题，5=相关 |
| 来源质量 | 引用是否可靠 | 1=可疑，5=权威 |
| 总体满意度 | 整体质量 | 1=差，5=好 |

**评估流程**：
1. 随机抽样，隐藏系统来源（盲评）
2. 3 个评估员独立打分
3. 取平均值，计算一致性（Kappa）

#### Q12: 怎么衡量缓存的效果？

**参考答案**：

**缓存命中率**：
```
命中率 = 缓存命中次数 / 总搜索请求次数

本项目实测: 27%
```

**成本节省计算**：
```
每次搜索 API 成本: ¥0.007
如果没有缓存，1000 次查询需要 4200 次搜索: ¥29.4
有缓存后，实际搜索 3066 次 (4200 × 0.73): ¥21.5
节省: ¥7.9 / 1000 次查询
```

**为什么能达到 27%**：
1. 用户经常问相似问题（"BERT 预训练" ≈ "BERT pre-training"）
2. 语义匹配阈值 0.85 比精确匹配命中率高

#### Q14: 评估时遇到的最大挑战是什么？

**参考答案**：

**挑战 1：答案质量难以自动评估**

```
问题：系统回答和参考答案可能表达不同但都正确
例如：
参考答案："BERT 用 MLM 和 NSP 两个任务预训练"
系统答案："BERT 的预训练包括掩码语言模型和下一句预测"
ROUGE-L 只有 0.3，但其实是对的
```

**解决方案**：
1. 关键点覆盖率（检查是否包含"MLM"、"NSP"等关键词）
2. 人工抽样评估
3. LLM-as-Judge（用 GPT-4 评估）

**挑战 2：测试集泄露风险**

```
问题：调参过程中可能"偷看"测试集
```

**解决方案**：
1. 验证集和测试集严格分开
2. 只在最终评估时使用测试集
3. 记录测试集使用次数（不超过 3 次）

#### Q17: 如果模型在测试集上表现很好，但上线后效果差，可能是什么原因？

**参考答案**：

**可能原因**：

| 原因 | 表现 | 解决方案 |
|------|------|----------|
| **分布偏移** | 真实用户问题与测试集不同 | 收集真实用户数据，持续更新测试集 |
| **测试集泄露** | 测试集无意中参与了训练 | 严格隔离，重新划分 |
| **评估指标片面** | 自动指标高但用户不满意 | 增加人工评估 |
| **环境差异** | 线上 API 延迟/失败率更高 | 压力测试，降级方案 |

**诊断方法**：
```python
# 收集线上 bad case
def collect_bad_cases():
    cases = []

        if log["user_feedback"] == "negative":
            cases.append({
                "query": log["query"],
                "answer": log["answer"],
                "reason": log.get("reason", "unknown")
            })
    return cases

# 分析 bad case 分布
bad_cases = collect_bad_cases()
reasons = Counter([c["reason"] for c in bad_cases])
```

#### Q18: 如何判断数据标注质量是否足够？

**参考答案**：

**指标 1：标注一致性（Inter-Annotator Agreement）**
```python
from sklearn.metrics import cohen_kappa_score

# 让两个标注员标同样的数据
labels_1 = [annotator1.label(x) for x in samples]
labels_2 = [annotator2.label(x) for x in samples]

kappa = cohen_kappa_score(labels_1, labels_2)
# kappa > 0.8: 很好
# kappa > 0.6: 可接受
# kappa < 0.4: 需要改进标注指南
```

**指标 2：模型学习曲线**
```
如果数据质量差：
- 训练 loss 下降慢
- 验证集 reward 波动大
- 模型行为不稳定
```

**指标 3：人工抽检**
```
抽 100 条，检查：
1. 动作标注是否合理
2. 奖励计算是否正确
3. 轨迹是否完整

质量达标标准：> 90% 正确
```

#### Q19: 除了你用的指标，还有什么指标可以评估检索系统？

**参考答案**：

**更多指标**：

| 指标 | 说明 | 适用场景 |
|------|------|----------|
| **NDCG@K** | 考虑位置加权的排名质量 | 结果有多个相关等级 |
| **MAP** | 平均精度均值 | 有多个正确答案 |
| **Recall@K** | 召回率 | 关注是否遗漏 |
| **F1** | 精确率和召回率的调和平均 | 平衡 P 和 R |
| **Answer Rate** | 能回答的问题比例 | 关注覆盖率 |
| **Fluency** | 答案流畅度 | 关注生成质量 |
| **Faithfulness** | 答案是否忠于来源 | 防止幻觉 |

**为什么本项目没全用**：
1. 简单场景下，Top-5 命中率足够
2. 指标太多会模糊重点
3. 核心关注：质量 + 效率 + 成本
