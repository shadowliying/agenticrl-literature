# 系统评测（指标与流程说明）

## 1. 评测目标

本评测用于回答三件事：

- 系统是否能完成任务（质量）
- 检索是否有效（命中与排序）
- 成本与效率是否可控（步数、时延、费用）

## 2. 评测数据与隔离原则

- 评测集：800 条（独立测试集，仅用于评测）
- 训练集：与评测集完全隔离，避免数据泄露
- RL 训练数据：2500 条，仅用于训练策略

## 3. 评测维度与核心指标

### 3.1 任务完成与答案质量

- 任务完成率（Completion Rate）
- 关键点覆盖率（Key-Point Coverage）
- ROUGE-L（与参考答案的文本相似度）
- 人工评分（准确性、完整性、相关性、来源可靠性）

### 3.2 检索质量

- Top-5 命中率（Hit@5）
- MRR（Mean Reciprocal Rank）
- 召回质量（是否命中期望来源）

### 3.3 效率与成本

- 平均检索次数
- 平均步数（Agent 调用总次数）
- 响应时间（P95）
- API 成本（平均 Token 消耗）
- 缓存命中率

### 3.4 稳定性与安全

- 无效检索比例
- 低分硬答比例（应拒答却回答）
- 失败重试率

## 4. 指标计算方式（可直接回答面试官）

### 4.1 质量相关

Completion Rate：
```
完成率 = 成功回答数 / 总问题数
```

Key-Point Coverage：
```
覆盖率 = 命中关键点数 / 关键点总数
```

ROUGE-L：
```
ROUGE-L = LCS(answer, reference) / len(reference)
```

### 4.2 检索相关

Hit@5：
```
Hit@5 = Top-5 结果包含正确来源的比例
```

MRR：
```
MRR = (1/rank_1 + 1/rank_2 + ... ) / N
```

### 4.3 效率与成本

平均检索次数：
```
平均检索次数 = 总检索调用数 / 总问题数
```

平均步数：
```
平均步数 = 总 Agent 调用数 / 总问题数
```

P95 响应时间：
```
95% 请求完成时间的上分位
```

缓存命中率：
```
缓存命中率 = 缓存命中次数 / 总检索次数
```

## 5. 参考阈值（来自既有文档设定）

- 任务完成率 > 75%
- 关键点覆盖率 > 80%
- ROUGE-L > 0.4
- Hit@5 > 80%
- MRR > 0.6
- 平均检索次数 < 3
- 平均步数 < 5
- P95 响应时间 < 30s
- 缓存命中率 > 25%
- 平均 Token 消耗 < 5000

## 6. 评测流程（三层）

### 6.1 离线自动评测

- 跑完整 800 条评测集
- 统计所有自动指标
- 输出分维度报告（质量、检索、效率、成本）

### 6.2 人工评测

- 从评测集随机抽样 50 条
- 评分维度：准确性、完整性、相关性、来源可靠性、整体满意度
- 多人独立评分，计算一致性（Kappa）

### 6.3 线上评测（如有真实流量）

- A/B 测试两个版本
- 记录用户满意度、完成率与负反馈
- 收集 bad case 作为回流样本

## 7. 基线对比与消融

- 规则基线 vs RL 决策
- 去掉 Reranker 的效果变化
- 去掉 Memory 的效果变化
- 去掉 Validate 的效果变化

参考结论表达（示例）：

- 完成率 68% → 79%
- 无效检索步数下降 33%
- Top-5 命中率提升到 82%
- API 成本下降约 27%

## 9. 面试官可能问的问题（含答法要点）

Q1：你怎么证明 RL 决策有效？
A：用规则基线对比，并做消融，展示完成率提升与检索步数下降。

Q2：为什么不能只看 ROUGE？
A：ROUGE 只能反映文本相似度，不代表事实正确，必须结合关键点覆盖与人工评测。

Q3：评测数据有没有泄露？
A：训练集与评测集完全隔离，评测集仅用于评测。

Q4：如果线上效果和离线评测不一致怎么办？
A：考虑分布偏移，补充真实问题，增加人工评测与 A/B 测试。

Q5：检索指标为什么用 Hit@5 而不是 Top-1？
A：检索系统通常有多条候选，Top-5 更能反映检索召回能力。
