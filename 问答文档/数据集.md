# 数据集（用于项目问答与评估说明）

## 1. 数据集总览

本项目的数据分为两大类，严格隔离，避免数据泄露：

- RL 训练数据：2500 条（用于训练决策策略）
- 系统评估数据：800 条（独立测试集，仅用于评估）

核心评价指标与数据紧密关联：

- 任务完成率
- Top-5 命中率
- API 成本
- 响应时间

## 2. 数据分成哪几个部分

### 2.1 RL 训练相关数据（2500 条）

- 训练集：2000 条
- 验证集：300 条
- RL 测试集：200 条

用途说明：

- 训练集用于策略学习
- 验证集用于调参与早停
- RL 测试集用于离线验证策略效果

### 2.2 系统评估数据（800 条）

- 独立测试集，不参与任何训练
- 用于评估整个系统的端到端效果
- 与 RL 训练数据完全分开

## 3. 数据从哪里来（来源与比例）

本项目的数据主要来自三条路径：

- 数据来源一：LLM 生成（约 60%）
  说明：通过 DeepSeek API 生成科研检索问题，覆盖 NLP/CV、事实问答、对比分析、代码请求等类型。

- 数据来源二：Query 改写增强（约 25%）
  说明：对已有问题进行多样化改写，提高表达多样性和语义覆盖。

- 数据来源三：公开数据集（约 15%）
  说明：从 SciQ、PubMedQA、QASPER、ScholarQA 等数据集中筛选与适配。

## 4. 数据是怎么得来的（构建流程）

### 4.1 LLM 生成流程

- 设计 Prompt，要求覆盖不同类型与难度
- 生成后进行去重与格式校验
- 过滤过短、无问号或非问题文本

### 4.2 Query 改写流程

- 对已有问题做多版本改写
- 强调语义一致、表达多样
- 用于扩充训练分布

### 4.3 公开数据集适配

- 选择学术问答类数据集
- 转换为本项目统一格式
- 过滤过于简单或不相关样本

## 5. 数据标注格式（核心示例）

### 5.1 RL 训练数据格式（轨迹数据）

```json
{
  "session_id": "train_001",
  "query": "介绍一下 BERT 的预训练方法",
  "trajectory": [
    {
      "step": 1,
      "state": {
        "query": "介绍一下 BERT 的预训练方法",
        "search_count": 0,
        "result_quality": "无",
        "cache_hit": false
      },
      "action": "OptimizerAgent",
      "action_output": "生成搜索词：BERT pre-training MLM NSP",
      "reward": 0.0
    }
  ],
  "total_reward": 1.0,
  "total_steps": 3,
  "success": true
}
```

要点说明：

- 轨迹由系统自动记录，不需要人工逐步标注
- action 是 Orchestrator/Worker 触发的动作
- reward 用于策略训练

### 5.2 系统评估数据格式

```json
{
  "id": "eval_001",
  "query": "Transformer 的自注意力机制如何计算？",
  "query_type": "技术原理",
  "difficulty": "中等",
  "reference_answer": "通过 Q/K/V 计算注意力权重...",
  "key_points": ["Q/K/V 矩阵", "缩放点积", "softmax", "多头"],
  "expected_sources": ["Attention Is All You Need", "arxiv.org/abs/1706.03762"]
}
```

要点说明：

- key_points 用于自动评估覆盖率
- expected_sources 用于检索质量评估

## 6. 数据质量控制（避免噪声与泄露）

- 去重与长度过滤：过短、过长、重复的问题直接剔除
- 格式过滤：非疑问句、非科研相关问题剔除
- 抽样人工检查：每 100 条抽检 10 条
- 多样性检测：用 BGE 向量聚类，检查类别覆盖
- 训练/评估严格分离：避免“看过测试集”

## 7. 必须掌握的知识点（面试常问）

- 训练数据和评估数据必须完全分开
- 评估指标要多维度，不能只看准确率
- 必须有基线对比与消融实验
- 轨迹数据可以通过系统日志自动收集
- 数据质量控制要有“过滤 + 抽检 + 多样性检查”组合

## 8. 面试官可能会问的问题（含参考回答）

Q1：你的数据是怎么来的？
A：60% 由 LLM 生成，25% 由问题改写扩增，15% 来自公开数据集（SciQ/PubMedQA/QASPER/ScholarQA）。

Q2：训练数据和评估数据怎么区分？
A：严格隔离。RL 训练 2500 条，评估 800 条完全独立，避免数据泄露。

Q3：轨迹数据是怎么标注的？
A：不人工标注，而是系统运行时自动记录状态、动作、奖励，形成轨迹样本。

Q4：如何保证 LLM 生成的数据质量？
A：做长度过滤、格式过滤、去重，并通过人工抽检和语义聚类检查多样性。

Q5：公开数据集怎么用到项目里？
A：筛选学术类问题，转换到统一格式，过滤太简单或不相关样本后再混入训练集。

Q6：评估时最重要的指标有哪些？
A：任务完成率、Top-5 命中率、响应时间、API 成本，分别对应质量、检索、效率、成本。

Q7：如果面试官问你遇到的数据问题？
A：主要是 LLM 生成噪声、难度分布不均、不同来源风格差异大。解决方式是过滤、改写增强和聚类检查。

Q8：怎么证明 RL 比规则系统更好？
A：用规则基线做对比，并做消融实验，展示完成率和检索步数的提升。

Q9：如果评估分数很高但线上效果不好怎么办？
A：考虑分布偏移和测试集泄露，补充线上真实问题，增加人工评估与 A/B 测试。

Q10：你如何保证评估公平和可复现？
A：固定随机种子、记录数据版本、保存训练与评估配置，确保可复现实验。
