# ✅ 强化学习学习文档（高级扩展版，对话形式）

## **一、强化学习基础（更深入版本）**

你：我到底要掌握哪些 RL 概念才够面试？  
我：至少要能把“问题 → MDP → 策略优化”的逻辑讲顺。核心要点是：

1. **MDP = (S, A, R, P, γ)**  
   - S：状态（问题 + 检索结果 + 进度）  
   - A：动作（SEARCH / READ / ANSWER / REPLAN / CODE）  
   - R：奖励（由 Validate 打分 + 效率）  
   - P：转移（由状态机规则控制）  
   - γ：折扣因子（长链路奖励）

2. **Policy πθ(a|s)**  
   - Orchestrator 本质是一个策略模型  
   - 输入是 state 文本，输出动作

3. **Trajectory τ = (s0,a0,r0,…,sn,an,rn)**  
   - 每条轨迹是一条完整问答过程  
   - GRPO 训练就是让“好的轨迹”权重更高

4. **Advantage A(s,a)**  
   - 衡量“这个动作比平均好多少”  
   - PPO 用 Critic 估计；GRPO 用组内排名估计

---

你：GRPO 的具体优势是什么？  
我：  
- **不需要 Critic**，训练稳定  
- **组内排名**天然带 baseline  
- 适合 LLM 场景（生成式任务）

## **二、SFT 与 GRPO 的分工（更细）**

你：为什么一定要 SFT → GRPO？  
我：  
因为没有 SFT，模型输出结构不稳定，GRPO 会“学乱”。

- **SFT 解决“格式和基本行为”**  
  比如：必须输出 Plan JSON  
- **GRPO 解决“策略是否更优”**  
  比如：什么时候检索、什么时候停止

一句话：  
**SFT 保证“能用”，GRPO 让它“更聪明”。**

## **三、奖励设计（完整算法级）**

你：奖励怎么算？  
我：奖励 = 过程 + 终局 + 惩罚。

### 1) 过程奖励（主导）
来源于 Validator 输出：
- `coverage`  
- `relevance`  
- `support_strength`  
- `consistency`  
- `info_gain`  
- `source_quality`  
- `freshness`

### 2) 终局奖励（辅导）
- `R_quality` 只在 ANSWER 才计算  
- 不能太大，否则奖励路径太远  

### 3) 惩罚项
- 重复检索  
- 空检索  
- 低分硬答  
- 超步数  

---

你：给我一个完整公式。  
我：  
```
R_total =
  w_quality * R_quality
+ w_sufficiency * R_sufficiency
+ w_info_gain * R_info_gain
+ w_efficiency * R_efficiency
- w_penalty * R_penalty
```

### 阶段一（过程强化）
- 0.25 / 0.35 / 0.25 / 0.15  

### 阶段二（质量平衡）
- 0.40 / 0.25 / 0.20 / 0.15

## **四、阶段一 / 阶段二怎么界定（必须会讲）**

你：阶段切换怎么定义？  
我：有两种明确方式：

**方法 A（固定进度，最易讲）**  
- 训练前 60% 步数 → 阶段一  
- 训练后 40% 步数 → 阶段二  

**方法 B（指标稳定切换，更工程化）**  
- `sufficiency_score` 均值 ≥ 0.75  
- `info_gain` 均值 ≥ 0.5  
- 连续 N 个 batch 波动很小  
满足即切换进入阶段二

一句话：  
> “我用训练进度做硬切换，必要时用指标稳定性做软切换。”

## **五、GRPO 训练机制（算法细节版）**

你：GRPO 怎么更新？  
我：GRPO 本质是“组内相对排名”更新。  

**步骤：**
1. 对同一个问题采样 K 条轨迹  
2. 用奖励函数打分  
3. 按奖励排序，得到相对 advantage  
4. 优化策略提高排名高的轨迹概率  

简化公式：  
```
L_GRPO = -E[ A_rank * log πθ(a|s) ] - β * H(πθ)
```

- `A_rank` 是组内相对排名  
- `H` 是熵正则

## **八、面试 Q&A（更深版 + 实践问题）**

### Q1：为什么不用 PPO？  
A：PPO 需要 Critic 网络估值，LLM 场景不稳定且成本高；GRPO 用组内排名更稳。

### Q2：GRPO 的优势？  
A：不需要 Critic；组内相对排名自带 baseline；更适合生成式任务。

### Q3：奖励如果设计不好会怎样？  
A：会出现“奖励欺骗”，例如模型疯狂检索刷分或低分硬答。  
解决：过程权重更高 + 惩罚项。

### Q4：如果终局奖励太高会怎样？  
A：奖励路径过远，模型学不到中间步骤，策略不稳定。

### Q5：SFT 的必要性？  
A：SFT 解决“结构化输出与格式对齐”，否则 GRPO 学习噪声很大。

### Q6：LoRA 为什么用 r=16？  
A：折中性能与成本，r 太小不够表达，r 太大训练成本高。

### Q7：如何判断 replan？  
A：Validate 评分过低 + 信息增益低 + 槽位缺失。

### Q8：如何评价模型决策变好？  
A：检索次数下降、命中率上升、完成率提升。

---

### Q9：你在实践中遇到过哪些问题？怎么解决？  
A：主要三类：  
1. **输出格式不稳定** → 先 SFT 对齐格式  
2. **策略绕圈（无效检索）** → 增加惩罚 + max_steps  
3. **奖励过远学不到** → 提高过程奖励权重  

### Q10：模型输出正确率低怎么排查？  
A：检查三点：  
- SFT 数据是否覆盖格式  
- Validate 规则是否过严/过松  
- 检索证据是否足够  

### Q11：为什么不让 Orchestrator 每一步都决策？  
A：成本高且不稳定。Orchestrator 负责 Plan，State 负责执行，只有 Replan 才调用 Orchestrator。  

### Q12：你怎么选 group size（轨迹条数）？  
A：一般 4～8。太小排序不稳定，太大成本高。  

---

### Q13：会不会出现 reward hacking？怎么处理？  
A：会，常见表现是“重复检索刷分”或“低分硬答”。解决方式：  
1. 增加惩罚项（重复检索/空检索/低分硬答）。  
2. 设置硬性门槛（缺槽位直接不足）。  
3. 提高过程奖励权重，压低终局奖励。  

### Q14：loss 曲线会怎么样？怎么判断是否正常？  
A：SFT 阶段 loss 应该稳定下降，JSON 格式正确率上升；GRPO 阶段 loss 不一定单调下降，更看 reward/完成率趋势。判断标准：  
1. 任务完成率上升。  
2. 无效检索步数下降。  
3. Top‑5 命中率提升。  
如果 loss 下降但 reward 不升，说明奖励设计或采样策略有问题。  

### Q15：阶段一/二用方法 A 怎么“控制”？用什么软件？  
A：不是用某个软件按钮，而是在训练脚本里按步数切换权重。  
实现方式：训练循环里统计 step/total_steps，达到 60% 就把权重从阶段一切到阶段二。  
配置位置可以写在训练脚本里（例如 GRPO 训练脚本）。  

### Q16：面试官问“你怎么实际操作切换”？  
A：我会说：在训练脚本里设置 phase_switch_ratio=0.6，每个 step 检查 step/total_steps，超过阈值就替换奖励权重表。  
这就是方法 A 的工程落地方式。  

**方法 A 的伪代码示例**  
```python
phase_switch_ratio = 0.6
for step in range(total_steps):
    if step / total_steps >= phase_switch_ratio:
        weights = phase2_weights
    else:
        weights = phase1_weights
    reward = compute_reward(weights, ...)
```
